Topology 01

Local UI + Local Agent + Local DB

Everything on one machine, three containers on one Docker network. The default starting point — nothing to reach over the internet.

3 containerslocal only

Minimal

docker network create fluxline-net

docker run -d --name fluxline-db --network fluxline-net \
  -e POSTGRES_PASSWORD=changeme \
  -v fluxline-db-data:/var/lib/postgresql/data \
  postgres:17-alpine

docker run -d --name fluxline-agent --network fluxline-net -p 3400:3400 \
  -v fluxline-agent-data:/data \
  -v /var/run/docker.sock:/var/run/docker.sock # build & test in toolchain containers \
  -v ~/.ai-sdlc:/vscode-bridge-registry:ro # vscode provider only \
  -e AI_SDLC_DATABASE_URL=postgres://postgres:changeme@fluxline-db:5432/postgres \
  suneshantanu/fluxline-agent:arm64

docker run -d --name fluxline-ui --network fluxline-net -p 3000:3000 \
  -e DATABASE_URL=postgres://postgres:changeme@fluxline-db:5432/postgres \
  suneshantanu/fluxline-ui:arm64

fluxline-agent
VariableRequiredDescription
AI_SDLC_DATABASE_URLyes*Postgres URL for run state. *Omit to fall back to in-memory (fine for trying things out — state is lost on restart).
AI_SDLC_CHECKPOINTERnomemory | postgres | remote — auto-picked from which URL/token vars are set; set explicitly to be sure.
AI_SDLC_API_TOKENnoPin the agent's own inbound auth token. Unset: one is generated on first boot and saved into /data.
AI_SDLC_ALLOWED_ORIGINSnoComma-separated browser origins allowed to call this agent. Default covers localhost only.
ANTHROPIC_API_KEY / OPENAI_API_KEY / GH_COPILOT_TOKENnoOnly for whichever code-gen provider(s) you enable in agents.yaml.
fluxline-ui
VariableRequiredDescription
DATABASE_URLyesSame Postgres the agent uses — or DB_HOST/DB_PORT/DB_USER/DB_PASSWORD/DB_NAME as discrete parts instead.
DB_POOL_MAXnoMax concurrent connections this UI instance opens. Default 10 per Node default.
DB_POOL_IDLE_TIMEOUT_MSnoHow long an idle pooled connection stays open before recycling. Default 30000.

First visit to :3000 creates the admin account — no separate bootstrap step or password variable.

Topology 02

Local UI + Local Agent, Remote DB

Both containers stay on your machine; only Postgres is elsewhere — a managed instance (RDS, Supabase, Neon...). No local fluxline-db container at all.

2 containersmanaged DB

Minimal

docker run -d --name fluxline-agent -p 3400:3400 \
  -v fluxline-agent-data:/data \
  -v /var/run/docker.sock:/var/run/docker.sock # build & test in toolchain containers \
  -e AI_SDLC_DATABASE_URL=postgres://USER:PASS@your-db-host.rds.amazonaws.com:5432/fluxline?sslmode=require \
  suneshantanu/fluxline-agent:arm64

docker run -d --name fluxline-ui -p 3000:3000 \
  -e DATABASE_URL=postgres://USER:PASS@your-db-host.rds.amazonaws.com:5432/fluxline?sslmode=require \
  suneshantanu/fluxline-ui:arm64
Detailed — discrete DB parts instead of one URL, plus pool tuning 
docker run -d --name fluxline-agent -p 3400:3400 \
  -v fluxline-agent-data:/data \
  -v /var/run/docker.sock:/var/run/docker.sock # build & test in toolchain containers \
  -e AI_SDLC_DATABASE_URL=postgres://USER:PASS@your-db-host:5432/fluxline?sslmode=require \
  -e AI_SDLC_CHECKPOINTER=postgres \
  suneshantanu/fluxline-agent:arm64

docker run -d --name fluxline-ui -p 3000:3000 \
  -e DB_HOST=your-db-host.rds.amazonaws.com \
  -e DB_PORT=5432 \
  -e DB_USER=fluxline \
  -e DB_PASSWORD=PASS \
  -e DB_NAME=fluxline \
  -e DB_POOL_MAX=20 \
  suneshantanu/fluxline-ui:arm64

Same variable tables as topology 01 — only the connection target changes. DATABASE_URL always wins over the discrete DB_* parts if both are set.

Topology 03

Remote UI, Local Agent

The UI is already hosted somewhere (ECS, a VPS, the shared team deployment) with its own database. The agent runs on your own machine and links to it with a personal access token — no local Postgres to run at all.

1 containerhosted UI

Minimal

# get a token: hosted UI → Settings → Agent tokens → New token
docker run -d --name fluxline-agent -p 3400:3400 \
  -v fluxline-agent-data:/data \
  -v /var/run/docker.sock:/var/run/docker.sock # build & test in toolchain containers \
  -e AI_SDLC_REMOTE_UI_URL=https://app.yourco.com \
  -e AI_SDLC_AGENT_TOKEN=fxln_pat_... \
  suneshantanu/fluxline-agent:arm64
Detailed — pin the checkpointer explicitly, add a code-gen provider 
docker run -d --name fluxline-agent -p 3400:3400 \
  -v fluxline-agent-data:/data \
  -v /var/run/docker.sock:/var/run/docker.sock # build & test in toolchain containers \
  -v ~/.ai-sdlc:/vscode-bridge-registry:ro \
  -e AI_SDLC_REMOTE_UI_URL=https://app.yourco.com \
  -e AI_SDLC_AGENT_TOKEN=fxln_pat_... \
  -e AI_SDLC_CHECKPOINTER=remote # implied by the two vars above, set here for clarity \
  -e ANTHROPIC_API_KEY=sk-ant-... \
  suneshantanu/fluxline-agent:arm64
fluxline-agent — this topology only
VariableRequiredDescription
AI_SDLC_REMOTE_UI_URLyesBase URL of the hosted UI this agent reports run history and workspace config to.
AI_SDLC_AGENT_TOKENyesPersonal access token from that UI's Agent tokens screen. Pairs with the URL above — the run history you see is tied to this exact token.
Topology 04

Agent Only, Headless

No UI container at all — talk to the agent's own HTTP API directly (scripting, CI, a thin custom frontend). In-memory run state by default.

1 container

Minimal

docker run -d --name fluxline-agent -p 3400:3400 \
  -v fluxline-agent-data:/data \
  -v /var/run/docker.sock:/var/run/docker.sock # build & test in toolchain containers \
  suneshantanu/fluxline-agent:arm64

# the token is printed to logs on first boot if you don't set one:
docker logs fluxline-agent | grep Bearer
Detailed — pin the token, add persistent Postgres state anyway

  -v fluxline-agent-data:/data \
  -v /var/run/docker.sock:/var/run/docker.sock # build & test in toolchain containers \

  -e AI_SDLC_CHECKPOINTER=postgres \

Appendix

Full variable index

Every variable either image reads, grouped by what it configures — for anything not covered by the four topologies above.

Core & networking — agent

VariableDefaultDescription
AI_SDLC_HOST0.0.0.0Already set inside the image — only override for unusual networking.
AI_SDLC_PORT3400Already set inside the image.
AI_SDLC_ALLOWED_ORIGINSlocalhost onlyComma-separated browser origins allowed to call this agent's API.
AI_SDLC_CHECKPOINTERauto-detectedmemory | postgres | remote — inferred from which DB/remote vars are set.

Data & paths — agent

VariableDefaultDescription
AI_SDLC_DATA_DIR/dataPersistent config + secrets root. Always mount a volume here.
AI_SDLC_AGENTS_CONFIG/data/agents.yamlProvider config — override only for a non-standard layout.
AI_SDLC_WORKSPACE_CONFIG/data/workspace.yamlActive workspace definition.
AI_SDLC_PIPELINE_CONFIG/data/pipeline.yamlPipeline/checks configuration.
AI_SDLC_CONTAINER_IDauto-detectedThis agent container's name/id, used to give build/test containers the same mounts (--volumes-from). Set only if detection fails.
-v /var/run/docker.sock:/var/run/docker.sock—Lets verification checks and dependency builds run in toolchain containers (Maven/Gradle/Node/Go/Python/Rust image picked from each repository's manifest, ./mvnw replaced by the image's mvn, caches in fluxline-toolchain-* volumes; ~/.m2/settings.xml, ~/.npmrc, pip.conf and gradle.properties from the agent's home are copied in). Without it, checks run in the agent's own shell. Control with check_runtime: auto | container | host in pipeline.yaml. Repositories and the run directory must be on a mounted volume.
